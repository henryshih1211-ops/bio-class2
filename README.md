# 生科2班 · 本周

26级生物科学类2班网页应用。React / Vinext，公开站仍为 GitHub Pages 静态输出。班级待办与作业从同源 JSON 清单读取，发布记录持久保存在 GitHub 仓库；管理员电脑上的本地发布台负责保存草稿和发布。没有公网上的写入接口或班委账号。

## 班级共享清单

- 手机“待办”页顺序：我的待办、班级待办、班级作业单、常用内务网站；桌面原有排版保留。
- `public/class-board.json` 为全班公开清单，部署后对应 `/bio-class2/class-board.json`。每分钟、页面回到前台及手动刷新时重新读取。
- “我已完成”保存在每位同学当前设备的 `bio-class2-board-checks-v1`，不会更改共享状态。负责人“结束事项”会更新全班的已结束列表。
- 支持课程筛选、置顶、北京时间截止日期、24小时内截止与逾期提示；当前没有主动推送通知。
- 旧 `shengke2-homework-draft-v1` 草稿只读保留，不会自动公开。

## 管理员发布

Mac 双击项目中的“打开班级发布台.command”，或运行 `npm run manage`，打开终端打印的本地地址后进入 `/manage/`。使用期间保持终端运行。

1. 添加班级待办或课程作业，填写要求、截止时间、负责人，可置顶。
2. 保存草稿：保存在忽略提交的 `.local-board/draft.json`，未发布给全班。
3. “预览并发布”核对完整清单，再点击“确认发布给全班”。
4. 发布台会检查线上版本，通过 GitHub API 依次更新 `main` 与 `gh-pages` 分支中的清单文件，保留其他文件和本机改动。若中途断网，下次发布会恢复尚未完成的更新，不会重复生成同一清单。测试用本地 Git 远程采用原子推送。
5. GitHub Pages 更新后，同学刷新或等待页面自动更新。发布台通过独立读取公网清单核对发布结果，不会把提交成功当作上线完成。

本地发布需现有 `github` 远程与可用的 GitHub Git 写入凭据。发布时从 Git 凭据助手在内存中取得凭据，仅发送给 `api.github.com`，不发送到网页或写入清单，不跟随重定向。读清单不需要凭据。发布台只接受回环地址、可信本机 Host 及同源请求；写操作还要求 JSON 和专用请求头，构建后的站点无此接口。多窗口草稿版本检查与远程非快进拒绝可避免静默覆盖。重新读取线上清单会先备份旧草稿到 `.local-board/backups`。

这是“你在电脑发布、同学手机查看”的第一阶段。学习委员独立登录、手机发布、附件和跨设备个人完成状态在后续阶段接入。

后续重新部署网站前，先从远程 `main:public/class-board.json` 同步最新清单，避免旧构建覆盖负责人刚发布的内容。发布网站保留远程头并使用非强制推送；不要以旧的本机清单重置线上清单。

## 共享功能验证

`npm run test:board` 在临时本地 Git 仓库测试保存、发布、重启持久化、独立读者获取相同内容、重试、版本冲突及文件保留；另外验证离线标识、无缓存错误、非法响应回退和截止日期。测试数据不会上传真实仓库。

## 功能与边界

- 教学周课表：2026-09-07为第1周周一，共20周。
- 23条固定排课记录；另展示3条英语/体育待定板块与第2—3周军事训练。
- 单周课程自动筛选，劳动教育仅第4周周五第5节。
- 个人待办、完成状态、常用网址仅存于当前来源的浏览器localStorage，不跨设备、不向班级同步。清除浏览器数据会删除这些个人记录。
- 未集成学校实时数据、通知后台、学生名单或敏感材料。
- 课表来源：用户提供的2026-08-27学校课表；以学校后续通知为准。
- 手机采用逐日列表，桌面采用周课程列。

## 本地开发

使用已安装的依赖与锁文件。npm run dev 启动；npm run build 构建；npx tsc --noEmit 检查类型。公开资源目录为dist/client。
